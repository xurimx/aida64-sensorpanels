# AIDA64 SensorPanels

OLED-friendly AIDA64 SensorPanel layouts and a drag-and-drop Panel Designer. Built for a 13" 4K OLED tablet used as a second screen (3840×2160, landscape) and published as a GitHub Pages site.

## Conventions

- Always use metric units (°C, MB, MB/s, mm). Never Fahrenheit or imperial.
- OLED first: pure black (`#000`) background, dim static markings, colour only on live values. Prefer line graphs (`LG`) over area graphs (`AG`) so large areas don't stay lit.
- After changing anything that feeds an export, rebuild and re-check the exported file (see Verify), not just the preview.
- Pages are self-contained single files. No CDNs or external JS; fonts and shared scripts are inlined at build time.
- The designer connects only when the user asks: to openrouter.ai or to Ollama on 127.0.0.1/localhost. Its CSP meta (`connect-src`) allows exactly those; nothing else may fetch.
- InfoPanel and SynQPanel (GPL-3.0) import `.sensorpanel` files. Use them for format knowledge only; copy no code.

**Build**
- Run `python build_site.py`. Add `--all` to re-render the Classic OLED images; that needs Pillow and a current Pillow changes the PNG bytes.
- On the owner's PC `python` isn't on PATH, so use `uv run --with pillow python build_site.py`.
- Commit `src/` and the generated site folders together. GitHub Pages deploys from `main` / root.
- Source pages are fragments (title, styles, body). `build_site.py` adds the doctype and charset for the site copies.

**Keeping the committed Classic panel**
- `src/classic/out/` must hold the committed panel bytes, otherwise every build rewrites `panels/` and `classic/`:
  `git show HEAD:panels/Classic_OLED_3840x2160.sensorpanel > src/classic/out/Classic_OLED_3840x2160.sensorpanel`

## AIDA64 panel formats

`.sensorpanel` (SPVER 100, reverse-engineered, cross-checked against public panels and AIDA64 8.25)
- Plain text, one item per line, **CRLF**, **cp1252** (`°` is the single byte 0xB0). Git treats `*.sensorpanel`, `*.spzip` and `*.reg` as binary.
- Header: `<SPVER>100</SPVER><SWVER>7.35.7000</SWVER>` then `<SPWIDTH>…</SPWIDTH><SPHEIGHT>…</SPHEIGHT><SPBGCOLOR>0</SPBGCOLOR>`.
- Tag order is free, every tag is optional, numbers can be floats (`1024.00`). Draw order is file order.
- Item IDs: `IMG`, `LBL`, `[GAUGE]<sensor>`, `[SIMPLE]<sensor>`, `[GRAPH]<sensor>`. A bare sensor ID (`<ID>TMOBO</ID>`) is an AIDA64 "sensor item": label + value + unit + bar.
- **Hidden items:** a `-` prefix on any ID hides it. A hidden `LBL` in the plain form is used as a group divider.
- **Images:** hex-encoded PNG in `IMGDAT`. Custom gauge frames are stored once at the end as `GAUSTAFNM`/`GAUSTADAT` pairs (sorted) and shared by name.
- **Custom gauge:** 16 state images in `STAFLS` (`|`-separated). State = floor((v − min) / (max − min) × 15), clamped 0–15. Stack several gauges with overlapping ranges for more steps.
  - A gauge with empty frames and `SHWVAL=1` prints its value centred on `ITMX`/`ITMY`.
  - `TYP`: `Custom`, or the built-in skins `Black`/`White`. `SIZ`: `S`/`M`/`L`.
- **Visible `LBL`:** `TXTSIZ FNTNAM LBL LBLCOL LBLBIS SHDCOL SHDDIS SHDDEP URL`. Its text supports macros `$CPUMODEL`, `$GPU1MODEL`.
- **Text:** `TXTSIZ` is in points; GDI rounds the em to whole pixels (round(pt × 96 / 72)). Text cell = OS/2 usWinAscent/usWinDescent; Segoe UI is 2210/514 per 2048.
- **SIMPLE:** `TXTBIR` = bold, italic, right-align. With right-align, `ITMX` is the right edge.
- **Colours:** BGR decimal, r + (g << 8) + (b << 16).
- **Graph:**
  - `TYP` is `LG` line, `AG` area or `HG` histogram. `GPHBFG` = background, frame, grid flags.
  - Other tags: `GPHSTP` px per sample, `GPHTCK`, `GRDDNS`, `AUTSCL`.
- **Sensor item tags:** `WID … SHWBAR BARWID BARHEI BARPLC(SEP|EMB|BVU|3LN) BARMIN BARLIM1-3 BARMAX`, plus fg/bg colours per band.
- **Windows scaling:** AIDA64 multiplies positions, text size and panel size by the Windows scale, but not images. `writePanel(model, progress, dpi)` divides positions and sizes by dpi/100 to compensate.

`.spzip` (AIDA64 7.50+)
- A ZIP of one `YYYY-MM-DD.sp2` (SPVER 200) plus loose PNGs named in `IMGFIL`/`STAFLS`. There are no `IMGDAT`/`GAUSTA*` lines.
- `IMG` has `BGIMG` (1 = stretched to the panel) and optional `RESIZW`/`RESIZH`; `GAUGE` may have `RESIZW`/`RESIZH`.
- Encoding: 7.50 and 7.70 (and the bundled 8.25 default) write cp1252; official 7.99/8.25 files are UTF-16LE with a BOM. The importer sniffs the BOM.
- FinalWire still calls SPZIP immature, so `.sensorpanel` stays the default export.

## Sensor lists (designer "Your PC")

- AIDA64 › Preferences › Hardware Monitoring › External Applications publishes readings. All of the following are off by default (`aida64.ini` `HWMonEnableRegistry/SharedMem/WMI=0`).
  - **No `S*` system sensors are ticked by default** (`HWMonExtAppItems`), so users must click **Select All**.
  - Values exist only while AIDA64 runs.
- **Registry:** `HKCU\Software\FinalWire\AIDA64\SensorValues`, REG_SZ `Label.<ID>` / `Value.<ID>`; labels are English.
  - `reg query … | clip` gives `    Label.TCPU    REG_SZ    CPU` lines.
  - `reg export … file.reg` writes UTF-16LE with a BOM.
- **Shared memory** `AIDA64_SensorValues`:
  - Content is ANSI text ending in NUL, XML records with no root: `<temp><id>TCPU</id><label>CPU</label><value>45</value></temp>`. Tags are `sys temp fan duty volt curr pwr flow`.
  - Parse leniently: the External IP item can inject junk.
- `parseSensorList()` and `inferHw()` are in `src/designer/js/pc.js`.
  - They normalize `SCC-1-01` to `SCC-1-1` and drop `*IPADDR` values.
  - P/E split: d = threads − cores. Hybrid CPUs without Hyper-Threading can't be told apart, so the theme setup can override it.
- dxdiag was rejected: it has no sensor readings and no AIDA64 IDs.

## Sensor IDs that matter here

- Core clocks/temps: `SCC-1-n`, `TCC-1-n` (no leading zero, even though the manual writes `SCC-1-01`).
- Thread load `SCPUnUTI`; drives `SDRVxUTI`, `SDSKnACT`, `SDSKnREADSPD`, `SDSKnWRITESPD`, `THDDn`.
- Network `SNICnDLRATE`, `SNICnULRATE`, `SNICnTOTDL`, `SNICnTOTUL`, `SNICnCONNSPD`.
- Memory `SMEMUTI`, VRAM `SVMEMUSAGE`; DIMM temps `TDIMMTSn`.
- Registry values `SREGVALS1–10` / `SREGVALD1–10` from `HKCU\Software\FinalWire\AIDA64\ImportValues`.
- Refresh rate `SVREFRATE` is the Windows mode of (most likely) the main display and doesn't follow VRR.

## Things that read 0 or go missing

- FPS needs RivaTuner Statistics Server (or Fraps) running.
- DIMM temps need Preferences › Stability › DIMM thermal sensor support, then an AIDA64 restart.
- Network: try NIC numbers until one moves, or let the designer pick the NIC with the most traffic from the sensor list.

## Builder internals (src/builder/template.html)

- **`DEFAULTS`** holds the owner's setup:
  - `nic: 6`, `cpuTemp: 'TCPUPKG'`, `gpuTemp: 'TGPU1DIO'`, two disks (C:, D:), six fan slots;
  - power scales (`cpuW` 200, `gpuW` 450, `tdpMax` 150), colours (`cpuColor` `#3dd9c5`, `gpuColor` `#a08cff`);
  - `res` 3840×2160, `dpi` 100, `hmode: 'media'`, `dimmA: 2`, `dimmB: 4`;
  - `extras`, all on: thr, limit, vramTemp, vramClk, memHist, dimm, hpwr, coolant, board, refresh, netx. UI checkbox IDs are in `XMAP`.
- **`build(cfg)`** lays out on a 3840×2160 design grid, scaled by `k = min(OW/W, OH/H)` and centred. It returns `{ items, imgs, w, h, k }`.
  - Every static mark goes into one `background.png`.
  - Helpers: `tl/tr/tc`, `caption`, `sectionTitle`, `gauge`, `simple`, `valueCenter`, `graph`, `bar`, `ring`.
- **Export** uses the shared `SP.writer.writePanel` and `SP.zip.makeZip`.
  - Inside the Claude artifact viewer it saves a `.zip` via `claude.use('downloads')`, because that viewer won't save `.sensorpanel`.
  - Everywhere else it downloads the `.sensorpanel` directly.
- Settings persist in localStorage under `modern-split-builder-v1`.

## Panel Designer internals (src/designer)

**Scripts**
- Each JS file is inlined as its own classic `<script>` with a `//# sourceURL`.
- `build.py` keeps two lists: `CORE_SCRIPTS` (logic, also loaded by the test harness) and `UI_SCRIPTS` (editor, ui, assist, app).
- Designer files share one global scope, so keep top-level names unique.

**Document** (`doc.js`)
- Shape: `{kind:'aida64-sensorpanel-design', v:1, name, panel:{w,h}, warm, hot, tokens, export:{format,dpi}, gen, nodes, assets}`.
- Nodes are widgets `{id,type,x,y,w,h,name?,locked?,hidden?,p}` or one-level groups `{type:'group', name, div?, children}`. `div` is the exact divider text.
- Colours are `#rrggbb` or `@token`.
- Hardware is stored as explicit values; `gen = {theme, hw, opts}` lets the user regenerate a theme.
- **`sanitizeDoc()` guards everything untrusted** (files, links, autosave). It keeps:
  - declared fields, sanitized by their spec;
  - other keys in `defaults()`, checked against the type of the default;
  - whatever `def.sanitize()` adds.
- A new prop that is neither a field nor in `defaults()` is dropped on reload unless `def.sanitize` keeps it.
- `setDoc()` canonicalizes every incoming doc through `sanitizeDoc`.
- Shared helpers: `remeasure(w, env)` (size follows content, keeping the anchor) and `swapSensor(w, from, to)` (every sensor field, rows included).

**Widgets** (`widgets.js`, `gauges.js`, `composites.js`)
- Each type is registered with `defineWidget({type, label, cat, kind, resize, defaults, fields, sensors, measure, anchor, scale, emit | expand})`.
- Primitives:
  - `text` (baked, or a native `LBL`), `value` (SIMPLE; centred values use the empty-frame gauge), `rect`, `image`, `graph`;
  - `bar` (cumulative stacks: the chunk must divide 15), `ring` (the builder's ring), `dial` and `meter` (exclusive needle stacks, ported from gen.py);
  - `customGauge`, `nativeGauge`, `sensorItem`, `rawItem` (opened panels).
- Composites (`coreTable`, `powerTable`, `storageTable`, `fanRow`, `readout`) expand to primitives; `_div` children only add divider labels. Detach replaces a composite with its parts.
- `WF.*` (in composites.js) places text and values by baseline/anchor exactly like the builder's helpers. `tableDefaults(type, hw)` gives the tables' starting props for a PC (palette and assistant).
- Snippets (`snippets.js`, `SNIP.*`, `PRESETS`) are ready-made groups used by the palette and the themes.

**Painter and compile** (`paint.js`, `compile.js`)
- `emit(P, p, box)` records static runs (canvas fns) and live items, in local coordinates.
- Gauge frames go to `FRAMES`, named `<prefix>_<hash>_<nn>.png` by content and drawn lazily.
- **Flatten rule** in `compileDoc()`: a static run goes into the background unless it covers pixels of a reading below it, tested pixel-exact against gauge frames. Then it becomes its own IMG at that point (dial hubs).
  - In snippets and themes, put static parts before live parts in a group, or they get lifted.
- `ASSETS` holds imported and user images. The asset id includes the file name, so identical frames with different names survive a round trip.

**Themes**
- `themeModern` / `themeClassic` lay out on 3840×2160, then `scaleDocContent()` scales and centres them.
- Parity is checked against the builder export and the committed Classic file (see Verify).

**Editor** (`editor.js`, `ui.js`, `app.js`)
- `APP` holds the state. Undo uses JSON snapshots; `edit(fn, key)` merges edits with the same key within 500 ms, and `edit(fn, key, {sticky: true})` however far apart (one assistant request). Any other edit, a drag or Undo/Redo ends the merge.
- Per-widget op caches are keyed by type, w, h, p and tokens, never x/y, so moving never re-renders.
- Pointer events everywhere, so touch works.
- `window.__designer` exposes test hooks; `UI.after` holds extra refresh callbacks (the assistant's selection chip).

**Assistant** (`assist-core.js`, `assist-net.js` in CORE_SCRIPTS; `assist.js` in UI_SCRIPTS)
- Routes: copy & paste (prompt to any chat, reply pasted back), OpenRouter (browser → openrouter.ai), Ollama (`http://127.0.0.1:11434`). The Claude viewer gets copy & paste only; sign-in needs https or localhost.
- Four tools for API models: `get_design`, `get_node`, `find_sensors`, `apply_ops`. The paste route uses the same ops in a ```json block.
- `AI.exec(doc, ops, ctx)` is the only way the assistant changes a design:
  - ops: add (type or preset), update, remove, duplicate, group, ungroup, order, replace_sensor, style, panel; `$ref` names last for one request (`ctx.refs`);
  - creates only the palette types and `PRESETS`, writes only declared fields (checked like `sanitizeField`, never `tags`, `frames`, `asset`, `slabel`), and leaves touched nodes canonical;
  - each op validates on copies and changes nothing when it fails; errors name what is allowed; warnings cover sensors not on the PC, OLED (area graphs, big fills), imperial units, outside the panel, overlaps.
  - a sensor given without a range gets the catalogue's (graphs, bars, rings, dials, readouts, meter scales).
- `assist.js` `aiApply()`: dry run on a copy; asks before removing more than 10 parts or 30 %; then swaps the copy in with one sticky `edit()`. Changed parts are selected; a Keep/Undo bar follows.
- Prompts: `AI.rules()` (house rules, ops, catalogue generated from `WT`, common sensor IDs) and `AI.summary()` (`<design_state>`; design text JSON-quoted with `<`/`>` escaped). Ollama gets the group-level summary and `aiFit()` trims history to `num_ctx`.
- Network (`assist-net.js`): `NET.fetch`/`NET.go` (tests set `window.__assistFetch`, `__assistNavigate`, `__assistWaitMs`); SSE and NDJSON readers; `OR.chat` assembles streamed tool calls and passes `reasoning_details` back unchanged; `OR.error` maps 401 (forget the key), 402, 429 (wait 15 s, 45 s), 408/502/503 (retry once).
- Only the parameters a model lists in `supported_parameters` are sent, plus `provider.require_parameters`.
- Keys (`KEYS`): sessionStorage by default, localStorage only with "remember". Never in IndexedDB, designs, links, files, chat or logs; error text is redacted.
- Sign-in (`PKCE`): S256 verifier/state in sessionStorage; `assistBoot()` runs before the `#d=` link handling, cleans `?code&state` from the address, and exchanges the code only if the state matches and it is under 10 minutes old.
- Ollama diagnosis when Connect fails: a no-cors probe tells "running but `OLLAMA_ORIGINS` doesn't allow this origin" from "not running"; a denied local-network permission means the browser blocked it.
- Storage: settings in STORE `assist`; the conversation in sessionStorage (`…assist-chat`), plain text only.

**Storage**
- IndexedDB `aida64-sensorpanels-designer`, with a memory fallback: autosave `doc:current`, recent designs, assets, and the PC list (`pc`).
- Share links: `#d=` + base64url(deflate-raw(JSON)), without images, cleared with `replaceState`.
- Design files: `.design.json`, with images inlined as data URLs.

## Verify

- **Builder exports byte-identical after shared-code changes:**
  - before the change: `uv run --with playwright python src/builder/check_export.py --all --hash-out before.json`;
  - after the change: `… --all --compare before.json`.
- **Designer:** `uv run --with playwright --with pillow python src/designer/check_designer.py [io pc catalog widgets themes editor assist pages]`. It covers:
  - format round trips: the builder export and the Classic file re-written byte-identical; the AIDA64 sample;
  - sensor lists; needle and segment sweeps; the flatten rule;
  - Modern Split parity with the builder (items, frames, positions ±1 px, background) and Classic parity with gen.py;
  - editor interactions, undo/redo, files, links, autosave;
  - the assistant with a fake network: executor (errors, warnings, refs, 1500 random ops stay canonical, ops equal the editor's commands), reply extraction, stream readers split at every byte, scripted OpenRouter and Ollama turns, failures (401/402/429, mid-stream error, Stop, round cap, delete confirm), the sign-in round trip on a local http server, and that the key never leaks;
  - 390 px on every page.
- The assistant needs real checks by hand: a real OpenRouter sign-in on GitHub Pages, an Ollama model with `OLLAMA_ORIGINS` set, and a copy-and-paste round trip.
- For gauge changes, check exactly one needle/state is visible at each value and that segment counts match values.
- Check the pages at phone width (390 px) for horizontal scrolling.

## Calibration (open; needs the owner's AIDA64)

`uv run --with pillow python src/tools/calibration.py` writes test panels and a README to `src/tools/out/calibration/`. They are waiting on screenshots and exports from the owner. Open questions:
- SIMPLE text placement for Bahnschrift, Consolas, Tahoma and Arial. `fontmetrics.js` predicts it; gen.py assumed Bahnschrift ascent 1.0 / descent 0.25, while the font says 0.994 / 0.206.
- Gauge state rounding at exact boundaries (DW1 = 2, 3, 30, 31 on range 0–30).
- Whether SPVER 100 honours `RESIZW`.
- Which `.spzip` variants import: stored entries; an extra `designer.json`; the 200 % approaches D (same as SPVER 100) and E (RESIZW).
- Whether a 20 KB hidden label survives.
- How AIDA64 8.25 writes its own exports.

Until then, the designer's ".spzip with designer.json" option is off by default, and `.spzip` uses approach D.
