# AIDA64 SensorPanels

OLED-friendly AIDA64 SensorPanel layouts for a 13" 4K OLED tablet used as a second screen (3840×2160, landscape), published as a GitHub Pages site.

## Conventions

- Always use metric units (°C, MB, MB/s, mm). Never Fahrenheit or imperial.
- OLED first: pure black (`#000`) background, dim static markings, colour only on live values. Prefer line graphs (`LG`) over area graphs (`AG`) so large areas don't stay lit.
- After changing anything that feeds an export, rebuild and re-check the exported file (see Verify), not just the preview.

## Layout

```
index.html                 landing page (hand-written)
builder/index.html         Modern Split builder      <- generated by build_site.py
classic/index.html         Classic OLED preview      <- generated
sensors/index.html         sensor reference          <- generated
panels/*.sensorpanel       ready-made Classic OLED file  <- generated
assets/*.webp              landing page thumbnails (1600×900, rendered from the panels)
src/builder/template.html  builder source: UI, panel layout (build()), preview simulation, export (writePanel())
src/builder/build.py       embeds Selawik into template.html -> modern-split-builder.html
src/builder/check_export.py  Playwright: export the default panel and sanity-check the file
src/classic/gen.py         Python/Pillow generator for the Classic OLED panel -> out/
src/classic/build_page.py  parses out/*.sensorpanel back in and builds the preview page
src/sensors/aida64-sensor-reference.html  sensor reference (hand-written data in CATS)
src/fonts/                 Selawik (Segoe UI stand-in) and Barlow Semi Condensed, with OFL licences
build_site.py              runs the builds and writes the site folders
```

Build: `python build_site.py` (add `--all` to re-render the Classic OLED images; needs Pillow). Then commit `src/` and the generated site folders together. GitHub Pages deploys from `main` / root.

Source pages are fragments (title, styles, body). `build_site.py` adds the doctype and charset for the site copies.

## Owner's setup (the builder defaults match it)

- Intel hybrid CPU, 6 P-cores + 8 E-cores (20 threads); one graphics card; AIO with pump.
- Two drives: Disk 1 = C:, Disk 2 = D:.
- Network adapter is **NIC6** (AIDA64 counts virtual adapters, so NIC1 reads 0).
- RAM in DIMM slots **2 and 4** (`TDIMMTS2`, `TDIMMTS4`).
- Three monitors with different refresh rates; the panel runs on the tablet.
- Windows scaling on the 4K screen may be 200 %; the builder's Windows scale setting compensates.

## AIDA64 `.sensorpanel` format (reverse-engineered, cross-checked against public panels)

- Plain text, one item per line, **CRLF** line endings, **cp1252** encoding (`°` is the single byte 0xB0). Git treats `*.sensorpanel` as binary so it never rewrites line endings.
- Header: `<SPVER>100</SPVER><SWVER>7.35.7000</SWVER>` then `<SPWIDTH>…</SPWIDTH><SPHEIGHT>…</SPHEIGHT><SPBGCOLOR>0</SPBGCOLOR>`.
- Item IDs: `IMG`, `LBL`, `-LBL` (hidden divider label), `[GAUGE]<sensor>`, `[SIMPLE]<sensor>`, `[GRAPH]<sensor>`.
- Images are hex-encoded PNG in `IMGDAT`. Custom gauge frames are stored once at the end of the file as `GAUSTAFNM`/`GAUSTADAT` pairs and shared by name.
- Custom gauge: 16 state images listed in `STAFLS` (`|`-separated). State = floor((v − min) / (max − min) × 15), clamped 0–15. Stack several gauges with overlapping ranges for more than 16 steps (Classic OLED needles do this). A gauge with empty frames and `SHWVAL=1` just prints its value centred on `ITMX`/`ITMY`.
- `TXTSIZ` is in points (px = pt × 96 / 72). Segoe UI GDI cell: ascent 2210/2048, descent 514/2048 of the em.
- `TXTBIR` third digit = right-align; then `ITMX` is the right edge.
- Colours are BGR decimal: r + (g << 8) + (b << 16).
- Graph: `TYP` `LG` line or `AG` area; `GPHSTP` px per sample, `GPHTCK`, `GRDDNS`, `AUTSCL`, `GPHBFG`.
- Windows scaling: AIDA64 multiplies positions, text size and panel size by the Windows scale but not images. `writePanel(model, progress, dpi)` divides positions and sizes by dpi/100 to compensate.

## Sensor IDs that matter here

- Core clocks/temps: `SCC-1-n`, `TCC-1-n` (no leading zero, even though the manual writes `SCC-1-01`).
- Thread load `SCPUnUTI`; drives `SDRVxUTI`, `SDSKnACT`, `SDSKnREADSPD`, `SDSKnWRITESPD`, `THDDn`.
- Network `SNICnDLRATE`, `SNICnULRATE`, `SNICnTOTDL`, `SNICnTOTUL`, `SNICnCONNSPD`.
- Memory `SMEMUTI`, VRAM `SVMEMUSAGE`; DIMM temps `TDIMMTSn`.
- Registry values `SREGVALS1–10` / `SREGVALD1–10` from `HKCU\Software\FinalWire\AIDA64\ImportValues`.
- Refresh rate `SVREFRATE` is the Windows mode of (most likely) the main display and doesn't follow VRR.

## Things that read 0 or go missing

- FPS needs RivaTuner Statistics Server (or Fraps) running.
- DIMM temps need Preferences › Stability › DIMM thermal sensor support, then an AIDA64 restart.
- Network: try NIC numbers until one moves.

## Builder internals (src/builder/template.html)

- `DEFAULTS` holds the owner's setup: `nic: 6`, `cpuTemp: 'TCPUPKG'`, `gpuTemp: 'TGPU1DIO'`, two disks (C:, D:), six fan slots, power scales (`cpuW` 200, `gpuW` 450, `tdpMax` 150), colours (`cpuColor` `#3dd9c5`, `gpuColor` `#a08cff`), `res` 3840×2160, `dpi` 100, `hmode: 'media'`, `dimmA: 2`, `dimmB: 4`, and `extras` (all on): thr, limit, vramTemp, vramClk, memHist, dimm, hpwr, coolant, board, refresh, netx. UI checkbox IDs are in `XMAP`.
- `build(cfg)` lays out on a 3840×2160 design grid, scaled by `k = min(OW/W, OH/H)` and centred. Returns `{ items, imgs, w, h, k }`. Helpers: `tl/tr/tc`, `caption`, `sectionTitle`, `gauge`, `simple`, `valueCenter`, `graph(sensor, label, x, y, w, h, lo, hi, col, auto = false, step = 3)`, `bar`, `ring`.
- Memory and VRAM tiles: with `memHist` on, a 0–100 % line graph (step 1 ≈ 9 min of history at a 1 s update) with an 85 % reference line replaces the segmented usage bar.
- Preview simulation: `SCEN` (idle, gaming, render), `HIST` history buffers (700 samples), `STRS` for text sensors.
- Export: `writePanel()` writes cp1252 bytes. Inside the Claude artifact viewer it saves a `.zip` via `claude.use('downloads')` (that viewer won't save `.sensorpanel`); everywhere else, including GitHub Pages, it downloads the `.sensorpanel` directly.
- Settings persist in localStorage under `modern-split-builder-v1`.

## Verify

- `python src/builder/check_export.py` (needs `pip install playwright` and `python -m playwright install chromium`): exports the default panel, checks CRLF, the size header and that every gauge frame is embedded.
- For gauge changes, check exactly one needle/state is visible at each value and segment counts match values.
- Check the pages at phone width (390 px) for horizontal scrolling.
